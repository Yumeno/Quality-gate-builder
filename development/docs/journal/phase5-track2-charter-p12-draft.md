6. **user の格上げ (GMP 参照)**: 「GMP など人間社会の厳格な管理ルールを参考にするなら、**利害関係が同一の存在が原則としては評価をすべきではない**」→ 独立性を「宣言すればよい設計軸」から「**原則 + 理由付き逸脱**」へ格上げ。GMP の品質部門/製造部門分離、ISO 19011「監査員は自分の仕事を監査しない」、four-eyes principle と同型。この光で P6 の真の祖先が確定: P6 は (a) 外部化されていない評価は監査座標系に乗らない (経路の規律) と (b) 利害同一者の評価は原則信頼できない (独立性原則) の**交点**であり、操作 agent の自己評価は両方に違反する最悪ケースだから真っ先に禁止された。逸脱許容の形式は qgb 既存の F-007 waiver パターン (理由 + decided_by + 証跡) を再利用する。なお独立性宣言の機械検証は不能 (自己申告) — 宣言は改竄防止でなく説明責任の宛先を作る装置であり、それで足りる (human_reviewed と同じ位置づけ)
7. **user の例外条件の確定**: 「評価機設計段階に人間側の承認決裁があるなら、そこの例外もアリ」→ 独立性原則からの逸脱 (利害同一の評価機構成) が成立する条件 = **評価機の設計・採用段階での人間の承認決裁 (記録付き)**。精密には: 人間の承認は利害の無さを作るのではなく (ソロ開発者は自製品が通ってほしい側でもある)、**説明責任の宛先が定まった決裁点**を作る — P6 の最深層 (帰結を引き受ける主体の承認が頂点に立つ) と同じ論理。承認は P8 の既存規律で縛る: 承認フラグは人間のみが立てる、decided_by を記録、逸脱は証跡から見える (P5/P11 の局所的意味の一部のまま)

## 2. P12 草案 (v0.1、文言は今後 user が練る)

### P12. 評価系もまた設計物である

**原則**
qgb が固定するのは評価主体ではなく、評価が判定根拠になるための経路である。検証段階の評価主体 — プログラム、機械計測、LLM/VLM を組み込んだ評価機、人間の検査員 — は利用者が設計・選択してよい。ただし、いかなる評価も、外部化された経路 (contract による宣言、実行ごとの証跡、再検査可能な手続き、説明責任の宛先) を通ってのみ判定根拠となる。

**根拠**
判定機の性能限界は静的でない。定量計測に限らず、揺らぐ評価者 (生成 AI、人間パネル) であっても、固定・集約・校正を施して経路の規律を守れば計測器になれる — 官能検査が計器化されてきたのと同じ道である。逆に、どれほど優れた評価者でも、経路を迂回した評価 (会話中の主観、記録されない目視) は監査の座標系に乗らず、判定根拠にならない。P6 が禁じてきたものの本質は「LLM であること」ではなく「外部化されていないこと」である。そして評価系 (REQ 集合 + 判定機群) それ自体が一個の設計物である以上、その被覆の妥当性と各判定機の校正は設計・レビューの対象であり、最終判断は人間が担う。

**適用**
- LLM/VLM を組み込んだ評価プログラムを `verification_type: command` の判定機として採用してよい。採用の規律: モデル・プロンプト・集約手続き (多数決/平均/閾値)・判定基準の固定と版管理、実行ごとの log、qualification (人間ラベルとの一致率等) の記録、採用判断の人間による承認
- 人間検査員の評価は、機械検証可能な attestation (確認者 ID・タイムスタンプ・対象 hash) として経路に渡す型で判定根拠にできる (`human_attestation`、Phase 2+ 設計項目の憲章上の位置づけ)
- `manual_check` が NOT_READY であるのは評価者が人間だからではなく、経路を通らないからである
- 評価系の被覆 (どの品質観点に REQ と判定機を立てるか) は利用者の設計判断であり、qgb は被覆の妥当性を機械保証しない。被覆のレビューは人間の責務である (LLM は advisory)
- **評価主体の独立性: 原則 + 理由付き逸脱** (GMP 型): 評価主体は被評価物の生成者・qgb を操作する agent と利害を共有しない構成を**原則**とする。利害同一の構成 (自己評価) を採る場合の成立条件: (1) その旨と理由の宣言 (waiver 同型、decided_by 記録)、(2) **評価機の設計・採用段階での人間の承認決裁** (承認フラグは人間のみが立てる = P8 規律)。逸脱は証跡から辿れること — 独立性の有無は当該 gate の ALLOW の意味の一部である (P5/P11)。評価機の provenance (作成者・運転者・生成者との関係、LLM 評価機ならモデル系統) を採用時に宣言する
