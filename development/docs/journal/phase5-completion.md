## 1. Phase 5 は何だったか

計画上の Phase 5 は「skill を作って配る」だった。実際に起きたことはもう一段深い: **qgb が「機械の道具」から「人間と LLM の共同作業の場」になった**。Phase 1〜3 が作ったのは検査の機械 (runner / decision / evidence / lock)。Phase 5 が作ったのは、その機械を**初見の agent が初見の利用者と対話しながら正しく使えるようにする言語** — skill という名の、qgb の使い方についての外部化された判断基準である。

これは憲章の再帰適用でもあった。qgb は「LLM の出力を機械証跡で検証せよ」と説く。Phase 5 はその説教自体 (skill 文言) を、決定論ビルド + golden 照合 + 両系譜リリース検証という機械証跡で検証し、canary という実走試験で「文言が行動を生むか」まで測った。**qgb の思想で qgb の配布物を作った**、というのが Phase 5 の一行要約である。

## 3. 転回点は 3 つあった

**(1) 憲章 v2.0 / P12 の誕生 (Track 2)。** 出発点は「LLM 評価の扱いに免責を書く」という私の弱い案で、user がこれを拒否したところから本物の議論が始まった。「評価機の設計開発段階も qgb の利用範囲」「人間の検査員すらインターフェースを守れば枠組みに入る」「利害同一の評価は原則不可、ただし評価機設計段階の人間承認決裁が例外条件」— この 3 つの user 発言が P12 の骨格になった。免責 (逃げ) を正の原則 (経路規律) に反転させたこの改訂は、Phase 5 の全成果物の中で最も寿命が長いと思う。詳細は `phase5-track2-charter-p12-draft.md` と philosophy.md §8。

**(2) canary の系統分離 (5.d)。** canary #1 は開始数分で運転 agent (私と同系統の Fable 5) に設営を看破されて「親切さのテスト」が消滅した。この失敗が「試験の設営者と受験者の系統を分ける」という P12 の実測例を生み、canary #2 (Sonnet 運転・ブラインド維持) の成功につながった。そして予期しなかった副産物: **Sonnet は「言われた通りにやり、言われないことはやらない」ため、skill 文言の欠陥がそのまま挙動に写る理想の測定器**だった。Fable 5 は地力で穴を暗黙に埋めてしまい、何も検出できない。「利用者代表が文言だけで完走できる水準が合格ライン」という skill の品質定義はここから来た。

**(3) 発見→リリースのループが回り始めたこと (5.d〜5.e)。** v0.1.2 以降の 4 リリースは全て「実走の発見 → Issue → 文言確定 (指揮) → 適用 (sonnet) → 独立レビュー → 機械検証 → タグ」の同型バッチで、1 バッチ数時間まで短縮された。独立レビューは 3 バッチ中 2 バッチで must-fix を実検出しており (取り残し / 番号衝突 / 記述矛盾)、省略した 1 バッチ (v0.1.5) では省略理由と代替検収を journal に明記した。**このループ自体が Phase 5 の隠れた成果物**であり、v0.1.6 以降も同じ型で回る。
